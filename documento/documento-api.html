Documento de la API: Open Library

LAD319 · Desarrollo de Aplicaciones Web — Actividad 6 · Emiliano Ovalle · Consulta: 24 de noviembre de 2026

1. Datos generales

Nombre de la APIOpen Library API (interfaz JSON del catálogo de libros de Open Library).
Quién la mantieneOpen Library, proyecto de Internet Archive, organización sin fines de lucro (501(c)(3)).
Documentación oficialhttps://openlibrary.org/developers/api
AutenticaciónNinguna. No requiere clave ni registro; las peticiones sin credenciales responden 200.
FormatoJSON (también ofrece YAML y RDF/XML en las mismas rutas).

2. URL base

https://openlibrary.org

3. Endpoints

EndpointRuta y parámetrosQué regresa
Lista GET /search.json
q=… (obligatorio) · page=1…N · limit=12 · fields=key,title,author_name,first_publish_year,cover_i,edition_count		 Un objeto con numFound (total de coincidencias), start y docs, que es el arreglo de obras de la página pedida.
Detalle GET /works/{ID}.json
ID = identificador de la obra, p. ej. OL893414W		 Un objeto de una sola obra: título, descripción, temas (subjects), portadas (covers) y fecha de primera publicación.

La lista no incluye la descripción ni los temas: esos datos solo existen en el detalle, por eso la página pide el detalle al abrir la ficha de un libro.

4. Ejemplo de respuesta real (fragmento recortado)

Lista — GET /search.json?q=dune&page=1&limit=3

{ "numFound": 48267, // número → total de obras "start": 0, // número → desplazamiento "docs": [ // arreglo → obras de la página { "key": "/works/OL893414W", "title": "Dune", "author_name": ["Frank Herbert"], "first_publish_year": 1965, "cover_i": 11481354, "edition_count": 155 } ] }

Detalle — GET /works/OL893414W.json

{ "title": "Dune", // objeto → una obra "key": "/works/OL893414W", "description": "Set on the desert planet Arrakis, Dune is the story…", "subjects": ["Dune (Imaginary place)", "Fiction", …], "covers": [11481354, 12375564, …], "first_publish_date": "1965" }

En la lista docs y author_name son arreglos aunque la obra tenga un solo autor; en el detalle description puede venir como texto o como objeto { "value": "…" }, y el código contempla ambas formas.

6. Reglas de uso, tal como aparecen en la documentación oficial

  • Límite de peticiones: 1 petición por segundo sin identificarse y 3 por segundo si se envía una cabecera User-Agent con el nombre de la aplicación y un correo de contacto. La propia documentación advierte que el abuso puede provocar limitación agresiva o bloqueo.
  • Caché: la guía pide cachear las respuestas siempre que sea posible. La página guarda cada URL en un Map y no repite peticiones.
  • Uso permitido: proyectos open source y de descubrimiento de libros, investigación y educación. No se debe usar como backend masivo ni para descargar el catálogo en bloque (para eso hay volcados mensuales en openlibrary.org/developers/dumps), ni hacer scraping del HTML, ni repartir peticiones entre varias IP.
  • Licencia y atribución: los datos bibliográficos de Open Library se publican para uso libre; el sitio pide identificar la fuente (Open Library / Internet Archive) y enlazarla. Las portadas pueden conservar derechos de sus editoriales, por lo que se muestran enlazadas desde su CDN, no se redistribuyen.
  • CORS: los endpoints usados responden con Access-Control-Allow-Origin: *, así que se pueden consumir directamente desde el navegador sin proxy (comprobado con peticiones reales).

Verificación: la URL base, ambos endpoints, las rutas y los valores de las tablas se comprobaron con peticiones reales a la API el 24 de noviembre de 2026, y coinciden con la documentación pública citada.
